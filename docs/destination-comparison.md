# Destination environmental comparison

`/compare/` lets visitors choose any two named destinations from the public map index and compare every mapped record assigned to each. It shows historical environmental ranges alongside their coverage, rather than treating missing data as zero or assigning an overall destination winner. A fresh page starts without a selected pair; shared URLs restore their selected destinations.

Open `/compare/?month=9` on the local server, or follow **Compare destinations** from Regions. Both destination fields reuse `DiveAtlasSearchResultsMenu.createFilterPicker`, the site's existing searchable filter control. Type a destination or country, then click a result or use the arrow keys and Enter. Country names and site counts distinguish the options. Clear search edits only the draft; Escape or leaving the field restores the committed label. The displayed data changes only after selecting a result. Native selects remain hidden backing state, with the other selected destination disabled. A programmatic duplicate change swaps the pair.

**Compare destinations** is also in the existing map and destination-page menus. `site-header.js` installs the same `/compare/` anchor with the shared `top-menu-dropdown-item` class in both menu shapes, before the About section. Repeated header mounting does not duplicate the link; no menu styles or open/close behavior are replaced.

The swap button between the destination fields reverses both columns and updates the URL without changing the shared month.

The shared month wheel selects any of the twelve months; destination changes preserve its value. Both destination IDs and the month are retained in the URL for reloads. Destination names link to the existing area browser; separate explore, map and save buttons are omitted to keep the comparison compact.

Each environmental reading keeps its range and site coverage visible. Detailed source-grid and missing-data tables are omitted from the page; the shared Sources & limitations disclosure retains methodology and source periods. Failed requests still expose the retry control and status.

## Existing components and behavior

The page is generated by `tools/generate_destination_comparison.py` using `page_shell`, `site_header_fallback` and `site_footer_markup`. It loads the existing SEO, region, destination and scroll-wheel stylesheets. Scoped layout rules in `assets/destination-overview.css` reuse existing theme tokens and controls; no new font, palette, popup or modal is introduced. The flat document layout follows `DESIGN.md`: a 32px heading, compact controls, quiet dividers and no modal-like outer frame. Search selectors and the shared month wheel occupy one control area; units sit beside the heading on desktop. Metric labels align with two destination columns, which remain side by side on phones. Successful query status uses the existing screen-reader-only class to avoid repeating the visible coverage summary. Header search, theme, language and share/contact windows remain owned by the shared site scripts.

Comparison copy is translated in all fifteen website languages, including separate Simplified and Traditional Chinese dictionaries. `destination-comparison-i18n.js` follows the existing per-feature dictionary/interpolation pattern used by saved trips. It reads the website's language through `document.documentElement.lang`; the shared `global-coral-map-lang` preference and `diveatlas:language-change` event remain authoritative. There is no separate comparison language setting. The header loads the dictionary once for the menu entry, and the comparison controller awaits that same promise.

Headings, labels, coverage/status templates, source notes, accessible names, empty search results and clear-search labels update with the shared language. Month names and numeric values use `Intl`. Language updates do not request environmental data again or reset the pair, month or units. Recorded destination/site/country names, source periods, coordinates, identifiers and required Copernicus attribution remain source data. The main comparison is excluded from the general detail-page text walker so interpolated copy has one translation owner.

Unit controls use the existing IDs and handlers from `seo-page-controls.js`; values convert from unrounded source numbers. Existing measurement preferences persist across pages. Evidence lists are created on demand so the initial comparison does not construct hundreds of hidden detail panels.

The shared search picker honors disabled native options and accepts `clearSelection: false` for required choices. Its default remains `true`, preserving ordinary optional-filter clearing. Its optional `getEmptyLabel` callback supplies localized empty-result copy without changing other callers. The picker still owns keyboard interaction, highlighting, clear-button styling and body-level popup geometry; no comparison-specific search styling or dropdown implementation is introduced.

## Data and scope

`destination-comparison-data.js` reads `/regions/area-index.json`, the existing public map index, instead of a separately maintained site snapshot or the narrower generated SEO page subset. The catalog follows all 1,437 public `place` memberships, including single-site destinations and normalized case variants. Same-named places in different countries remain separate. Country-only legacy records do not become invented destinations. Site records are deduplicated by persistent ID within each selected membership. Bali / Komodo currently have 138 / 63 records; Bali Sea remains separate. Similar physical site names are not merged speculatively.

The module reuses `DiveAtlasConditionsService` and its production temperature, transparency, current and wave samplers without changing any sampling rule. Its fetch adapter resolves nested-page data URLs from the app root and honors the deployment-owned external data base. Only the selected destinations are queried. Six concurrent site queries bound request fan-out, and at most twelve destination/month promises are cached. Retry re-queries all records for the selected pair/month. A generation counter prevents an older pair or month from repainting newer results. Map extents reuse `DiveAtlasAreaSearch.bounds`, including its date-line handling.

Each measure reports the minimum/maximum of valid site queries, valid/total records, rounded coverage percentage, distinct source cells, missing cells and request failures. The destination summary counts records with all four measures. Shared source cells are not independent observations; these ranges are not area averages, seasonal extremes or confidence intervals. No suitability score is shown.

Baseline/depth metadata remains explicit: temperature at 5 m, WOA23 1991–2020; Secchi transparency 2016–2025; model currents at the 10 m target (~9.57 m source), 1993–2016; significant wave height 1993–2020. Secchi transparency is not measured horizontal dive visibility. Historical monthly currents do not resolve tidal peaks. The existing stride-4 current query grid can select masked cells around Komodo; no nearby-cell fallback or finer query dataset is introduced here. September's complete coverage remains 71/138 for Bali and 18/63 for Komodo.

## Regeneration and verification

From the repository root:

```powershell
python tools/generate_destination_comparison.py
node --test tests/unit/destination-comparison.test.js tests/unit/destination-comparison-i18n.test.js tests/unit/dive-conditions-model.test.js tests/unit/dive-conditions-service-metadata.test.js
$env:PLAYWRIGHT_PORT='8765'
npx playwright test destination-comparison.spec.js
```

The local session uses the repository-root server on port 8765. Without an existing server, Playwright starts the repository's normal test server. Static Pages assembly already includes the new HTML and JS through its normal file selection; this change does not alter publishing configuration or deploy anything.

Unit coverage checks every public place membership, same-name country separation, single-site inclusion, selected-only queries, valid zero versus missing/error accounting, shared cells, bounded concurrency, caching and retry. Browser checks exercise the real local datasets, typed destination/country search, keyboard and pointer selection, empty results, draft dismissal, clear-without-unselecting, ordinary optional-filter clearing, duplicate prevention, pair/month URL persistence, shared controls, linked destination names, retry after failed requests, source disclosures, discovery from Regions, and desktop/mobile popup bounds. The source rules and results are inspectable; AI-assisted implementation is not a substitute for review.

Translation tests verify dictionary completeness and placeholder parity for all fifteen locales, switch the comparison through each existing language option, preserve chosen state and network request counts, check Chinese copy after reload, and change the map menu label through the visible language control.


The destination overview shows mapped-site totals only. The all-four-measures summary and per-site disclosures are omitted from this compact view; measure-specific coverage remains visible.

Green text highlights compare ranges using an explicit preference: warmer temperature, higher transparency, lower modeled current speed and lower waves. Both endpoints must favor the same destination (one may tie); identical, mixed, missing or request-failed ranges stay neutral. No midpoint is treated as an average. Coverage remains visible, and the translated legend explains that the highlight is not a safety rating.

Destination photos sit above their linked names below the selectors and follow destination swaps. Photo credits are retained in Sources & limitations. The comparison generator reuses reviewed destination-page images and complete attribution captions through the existing photo assignment area keys. Destinations without an assigned photo show no substitute image; photo URLs and licensing remain owned by the existing destination pages.

At widths up to 720px, the destination search fields stack with a swap button on the right and the shared month wheel to their left. Desktop retains its horizontal fields. The month and destination pair persist across viewport changes. Photos and metric values remain in two columns on mobile.
